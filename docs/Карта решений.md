# Карта ключевых решений

## 2026-10-02

### Канонический репозиторий
Принято решение использовать `OlegStrateg/anait` как основной Git-репозиторий проекта.

### Ядро продукта
Главная ценность Анаит — психология, долговременная персональная память и ощущение глубоко понимающего собеседника. Таро является инструментом, а не конечным товаром.

### Память
Полную историю нельзя передавать модели на каждом запросе. Нужны структурированный профиль пользователя и выборка только релевантных воспоминаний.

### Монетизация
Бесплатный слой должен быть сам по себе полезным. Платный слой продаёт глубину разбора, а не искусственно скрытый конец бесплатного ответа.

### Секреты
Telegram Bot Token и любые API-ключи запрещено коммитить в репозиторий. Локально — `.env`; на сервере — Environment Variables / Secrets.

### LLM-провайдер Lite MVP
Для работы с GPT в Lite MVP используется API Master как внешний LLM-шлюз.

В коде используются только переменные окружения:
- `LLM_API_KEY`
- `LLM_BASE_URL`
- `LLM_MODEL`
- `LLM_API_STYLE`

Начальная модель по умолчанию: `gpt-6-luna`.

Реальный ключ API Master в GitHub не хранится.

### Runtime Lite MVP
От Vercel отказались. Lite MVP работает как обычный постоянно запущенный Node.js-процесс через Telegram Long Polling.

Причины:
- не нужен публичный домен и webhook;
- меньше инфраструктуры для раннего MVP;
- переносится на любой VPS/сервер;
- легко запускать через Docker Compose;
- архитектура не привязана к конкретному облачному провайдеру.

Для 24/7 работы процесс запускается через Docker Compose с `restart: unless-stopped`.

### Второй параллельный MVP
Запускается отдельный Telegram-бот для упрощённой версии продукта с отдельным bot token.

Цель второго MVP — быстро откатать:
- психологическую методику Анаит;
- долговременную память;
- тарологические сценарии и продуктовую линейку;
- баланс бесплатной и платной ценности;
- нативную воронку;
- стиль общения;
- конверсию в оплату и возврат пользователя.

В Lite MVP сознательно не являются приоритетом:
- сложные анимации;
- озвучка;
- видео и тяжёлые визуальные эффекты;
- дорогая сценическая подача.

Текущая визуально сложная версия не удаляется и не переделывается. Она сохраняется как кандидат для более дорогих раскладов и премиальной подачи после проверки ядра продукта.

### Архитектурный принцип двух версий
Lite MVP и визуально сложная версия должны в перспективе использовать одно продуктовое ядро: память, психологию, Таро, аналитику, платежи и пользовательские данные. Различаться должна главным образом оболочка и уровень подачи.

### Стартовая продуктовая лестница Lite MVP
Для первичной проверки достаточно трёх уровней:
1. Быстрый вход — 1 карта / короткий ответ.
2. Основной массовый формат — 3 карты.
3. Глубокий платный разбор — 5–7 карт.

Большие расклады на 10–12+ карт и премиальная постановка не являются приоритетом первого Lite-релиза.
